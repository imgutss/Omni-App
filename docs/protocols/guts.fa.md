# GUTS · راه‌اندازی با Google Apps Script

[English](guts.md) · [همهٔ راهنماها](README.md)

**[دانلود فایل Code.gs](https://github.com/imgutss/Omni-App/releases/download/v1.0.0/Code.gs)** · **[دیدن کد](../guts/Code.gs)** · **[ورود به Google Apps Script](https://script.google.com/)**

این آموزش برای **Certificate mode (Apps Script fetch)** است: وب‌سایت‌های معمولی را Apps Script دریافت می‌کند و به کلاینت برمی‌گرداند. در این حالت به VPS، نود خروجی، `EXIT_URL` یا آدرس `/g` نیاز نداری. دانلود بالا **سورس Google Apps Script** است؛ با APK اندروید یا باینری GUTS اشتباه نگیر.

## پیش از نصب گواهی، این را بدان

Fetch برای HTTP/HTTPS در مرورگرها و برنامه‌هایی است که به CA نصب‌شده توسط کاربر اعتماد می‌کنند. HTTPS روی گوشی با گواهی شخصی تو باز و دوباره رمز می‌شود؛ درخواست‌های معمولیِ عبوری از Apps Script برای همان اسکریپت/محیط اجرا قابل مشاهده‌اند. این حالت تونل خام و ماتِ TCP، حمل UDP یا راه‌حل همگانی تماس و بازی نیست.

**فقط CA ساخته‌شده توسط Omni خودت را نصب کن. CA دیگران را نصب نکن و کلید خصوصی CA خودت را هم به کسی نده.** برنامه‌های دارای certificate pinning یا برنامه‌هایی که CA کاربر را قبول نمی‌کنند ممکن است کار نکنند. برای بانکداری و نشست‌های حساس از این حالت استفاده نکن.

## ۱ · رمز مشترک بساز

روی یک دستگاه مطمئن، یک رمز تصادفی بساز:

</div>

```sh
openssl rand -hex 32
```

<div dir="rtl">

همین مقدار باید هم در `AUTH_KEY` اسکریپت و هم در **Shared key** پروفایل Omni باشد. آن را همراه آدرس دیپلوی عمومی نکن.

## ۲ · Code.gs را در گوگل دیپلوی کن

1. **[Code.gs را دانلود کن](https://github.com/imgutss/Omni-App/releases/download/v1.0.0/Code.gs)**. اگر مرورگر کد را نمایش داد، فایل را ذخیره کن یا از لینک «دیدن کد» کل محتوا را بردار.
2. با حساب خودت وارد [script.google.com](https://script.google.com/) شو و **New project** بساز.
3. فایل پیش‌فرض `Code.gs` را باز کن و تمام محتوایش را با کد فایل دانلودشده جایگزین کن.
4. فقط مقدار `AUTH_KEY` را با رمز خودت پر کن:

</div>

```js
const AUTH_KEY = "YOUR_NEW_RANDOM_SHARED_KEY";
```

<div dir="rtl">

5. **Save** بزن.
6. **Deploy → New deployment → Web app** را انتخاب کن.
7. **Execute as: Me** و **Who has access: Anyone** را بگذار. endpoint بدون ورود قابل دسترس می‌شود، ولی عملیاتش رمز مشترک می‌خواهد.
8. اگر گوگل مجوز خواست، دسترسی‌های پروژهٔ خودت را بررسی و تأیید کن؛ مجوز پروژهٔ ناشناس را کورکورانه تأیید نکن. سیاست بعضی حساب‌های Workspace اجازهٔ Web app عمومی نمی‌دهد.
9. نشانی نهایی که به **`/exec`** ختم می‌شود را کپی کن:

</div>

```text
https://script.google.com/macros/s/YOUR_DEPLOYMENT_ID/exec
```

<div dir="rtl">

آدرس ویرایشگر و `/dev` جای این نشانی نیستند. برای به‌روزرسانی دیپلوی قبلی، **Deploy → Manage deployments → Edit → Version: New version → Deploy** را انجام بده؛ Save تنها، نسخهٔ عمومی را عوض نمی‌کند.

## ۳ · پروفایل داخل Omni

از **+ → GUTS** وارد شو:

| فیلد | مقدار |
| :--- | :--- |
| Certificate mode (Apps Script fetch) | **روشن** |
| Doors (Apps Script web apps) | آدرس `/exec`؛ اگر چند دیپلوی متعلق به خودت داری، هر کدام در یک خط |
| Shared key | دقیقاً همان `AUTH_KEY` |
| Google edge address(es) | برای شروع `auto` |
| Edge SNI | برای شروع `www.google.com` |

این فایل عملیات نود خروجی را پیاده‌سازی نمی‌کند؛ با همین فایل، حالت Certificate/Fetch را روشن نگه دار.

## ۴ · گواهی شخصی همین گوشی را نصب کن

1. در ویرایشگر GUTS روی **Create / install my certificate** بزن.
2. Omni یک CA محلی می‌سازد و گواهی عمومی `omni-guts-ca.crt` را در Downloads قرار می‌دهد.
3. نصب اندروید را برای **CA certificate** کامل کن. مسیر در برندها فرق می‌کند؛ معمولاً **Security → Encryption & credentials → Install a certificate → CA certificate** است.
4. اگر نصب‌کننده اثرانگشت نشان می‌دهد، SHA-256 آن را با مقدار داخل Omni تطبیق بده. فایل گواهی عمومی است؛ کلید خصوصی باید خصوصی بماند.
5. پروفایل را ذخیره و انتخاب کن، وصل شو و با مرورگری که CA کاربر را قبول می‌کند امتحان کن.

نصب CA یک تصمیم امنیتی است، نه اخطاری برای ردکردن بی‌توجه. اگر دیگر از این حالت استفاده نمی‌کنی، CA مربوط را در تنظیمات اندروید بررسی/حذف کن؛ با حذف آن HTTPS وابسته به Fetch دیگر کار نمی‌کند.

## ۵ · لبهٔ مناسب شبکه‌ات را پیدا کن

اگر مسیر جواب نداد، **Scan this network for a working edge** را در پروفایل بزن. اسکنر زوج‌های Google edge و SNI را روی همان شبکه امتحان می‌کند؛ نتیجهٔ انتخاب‌شده را ذخیره کن. IP مناسب شبکهٔ فرد دیگر، IP تضمینی برای شبکهٔ تو نیست.

نامزد دستی هم باید لبهٔ واقعی و سازگار گوگل باشد، نه IP تصادفی CDN. بازشدن صفحهٔ `/exec`، پینگ سبز یا یک بررسی ساده به‌تنهایی نشان نمی‌دهد HTTPS برنامهٔ مقصد به CA اعتماد کرده و کامل کار می‌کند.

## خطاهای رایج

| خطا یا نشانه | بررسی |
| :--- | :--- |
| `AUTH_KEY is empty` | رمز را در کد بگذار، Save و New version دیپلوی کن. |
| `unauthorized` | رمز اسکریپت و Shared key را دقیق تطبیق بده؛ نسخهٔ دیپلوی را بررسی کن. |
| `does not advertise fetch` | کد Fetch را دیپلوی کن، نه کد دروازهٔ نود خروجی. |
| صفحهٔ ورود گوگل به‌جای JSON | دسترسی Anyone، سیاست حساب و نشانی `/exec` را بررسی کن. |
| خطای گواهی | نصب CA شخصی، fingerprint و اعتماد مرورگر را بررسی کن. |
| بعضی اپ‌ها کار نمی‌کنند | اعتماد به CA کاربر و pinning در اپ‌ها متفاوت است؛ Fetch، TCP/UDP خام نیست. |
| پاسخ بیش از حد بزرگ | این اسکریپت پاسخ معمولی بیش از ۸ MiB را رد می‌کند؛ در صورت پشتیبانیِ مقصد و کلاینت، درخواست Range مناسب لازم است. |
| خطای سهمیه یا مهلت | سهمیهٔ جاری Apps Script و مصرف حساب را ببین؛ مصرف را کم کن یا تا بازگشت ظرفیت منتظر بمان. |

بعضی درخواست‌های HTTPS مربوط به Google/YouTube در هسته از مسیر مستقیم edge و نه `UrlFetchApp` می‌روند؛ کارکرد آن هم به مسیر انتخابی وابسته است و تضمین استریم عمومی نیست.
