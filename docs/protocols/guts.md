# GUTS · Google Apps Script Fetch mode

[فارسی](guts.fa.md) · [All guides](README.md)

**[Download Code.gs](https://github.com/imgutss/Omni-App/releases/download/v1.0.0/Code.gs)** · [Read the source](../guts/Code.gs) · [Open Google Apps Script](https://script.google.com/)

This guide uses **Certificate mode (Apps Script fetch)**. Apps Script fetches ordinary websites for the client; you do not need a VPS, an exit node, `EXIT_URL`, or a `/g` address for this mode. The download is a Google Apps Script source file, **not** the Android app or a native GUTS binary.

## Before installing a certificate

Fetch mode handles HTTP/HTTPS in browsers/apps that trust a user-installed CA. HTTPS is terminated and re-created on your device using your own local CA; ordinary requests passing through Apps Script are visible to that script/runtime. It is **not** an end-to-end opaque raw TCP tunnel, UDP transport or a universal solution for calls/games.

Use only a CA generated by your own Omni installation. Do not install another person's CA or share your CA private key. Apps that reject user CAs or pin certificates may not work. Do not use this mode for sensitive banking sessions.

## 1 · Create one private shared key

On a trusted machine:

```sh
openssl rand -hex 32
```

Keep the value private. The same value belongs in Apps Script's `AUTH_KEY` and Omni's **Shared key** field. Never publish the key together with the deployment URL.

## 2 · Deploy Code.gs

1. Download [Code.gs](https://github.com/imgutss/Omni-App/releases/download/v1.0.0/Code.gs). If your browser previews it, save the file or use [View source](../guts/Code.gs) and copy the full contents.
2. Open [script.google.com](https://script.google.com/), sign into your own account, and create a new project.
3. Open the default `Code.gs`, replace its contents with the downloaded file, and set only this configuration value:

```js
const AUTH_KEY = "YOUR_NEW_RANDOM_SHARED_KEY";
```

4. **Save** the project.
5. Select **Deploy → New deployment → Web app**.
6. Choose **Execute as: Me** and **Who has access: Anyone**. The endpoint is reachable anonymously, but its operations require your shared key.
7. Authorize your own script when prompted. Review the requested permissions and confirm only the project you created. Organization/Workspace policies can restrict public Web app deployment.
8. Copy the deployed URL ending in **`/exec`**, for example:

```text
https://script.google.com/macros/s/YOUR_DEPLOYMENT_ID/exec
```

Do not use the editor URL or the development `/dev` URL. When updating an existing deployment use **Deploy → Manage deployments → Edit → Version: New version → Deploy**; saving the editor alone does not update the public endpoint.

## 3 · Configure Omni

Open **+ → GUTS**.

| Field | Value |
| :--- | :--- |
| Certificate mode (Apps Script fetch) | **On** |
| Doors (Apps Script web apps) | The `/exec` deployment URL; one per line if you own more than one |
| Shared key | Exactly `AUTH_KEY` |
| Google edge address(es) | Start with `auto` |
| Edge SNI | Start with `www.google.com` |

This script does not accept exit-mode session operations. Keep certificate/Fetch mode on when using it.

## 4 · Create your device certificate

1. Tap **Create / install my certificate** in the GUTS editor.
2. Omni creates the local CA and exports the public certificate `omni-guts-ca.crt` to Downloads.
3. Complete Android's **CA certificate** installation. Depending on the device this may be under **Security → Encryption & credentials → Install a certificate → CA certificate**.
4. Compare the SHA-256 fingerprint shown by Omni with Android's installer if available. The certificate is public; the private key must stay private.
5. Save the profile, select it and connect. Test with a browser that trusts your user-installed CA.

A certificate/CA prompt is a security-sensitive step, not a warning to click through blindly. If you stop using this mode, review/remove its installed CA in Android settings. Removing it prevents dependent Fetch-mode HTTPS from working.

## 5 · Find a usable Google edge

If the route fails, use **Scan this network for a working edge** in the profile. The scanner tries Google-edge/SNI pairs on the current network; save the selected result. A result from someone else's network is not a universal working IP.

For manual candidates, only use actual compatible Google edges, not arbitrary CDN IPs. Basic checks, an open `/exec` page or a green ping alone do not prove that an HTTPS application trusts the CA or that a full request succeeds.

## Troubleshooting

| Symptom | Check |
| :--- | :--- |
| `AUTH_KEY is empty` | Set it in Code.gs, save, deploy a new version. |
| `unauthorized` | Compare the script key and Omni Shared key exactly; check the deployed version. |
| `does not advertise fetch` | Verify you deployed this Fetch script, not an exit-door script. |
| Login page instead of JSON | Check deployment URL/access policy; use the deployed `/exec` endpoint. |
| Browser certificate error | Check your own CA installation, trust settings and fingerprint. |
| Only some apps work | User-CA trust/certificate pinning differs by app. Fetch is not raw TCP/UDP. |
| Response too large | This script rejects ordinary responses over 8 MiB; use a compatible HTTP Range client/request where appropriate. |
| Quota/time-limit errors | Check current Apps Script quotas and your account's usage; wait or reduce demand. |

Google/YouTube HTTPS can use a separate direct edge path in this engine rather than `UrlFetchApp`; its availability still depends on the selected route. Do not infer general streaming support from that behavior.
